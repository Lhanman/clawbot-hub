# Spec Delta

## Purpose

规定怎么让一个项目用上这个服务：登记一次（名字、密钥、前缀、保底和上限条数），之后只靠密钥通信；一个项目出问题或密钥泄露，一条命令就能断开它；项目之间互相看不到对方的东西。服务只认密钥，不管项目用什么语言、在哪个仓库、跑在哪里。

## ADDED Requirements

### Requirement: 登记项目

`hubctl project add <名字> [--prefix <前缀>] --guaranteed <条> --cap <条> [--default] [--label <标签> | --no-label] [--push-only]` MUST 登记一个项目并**只打印一次**它的密钥。校验：

- **名字**：`^[a-z][a-z0-9-]{1,31}$`，不能与已有的项目（含已移除的）重名；以下划线开头的名字是服务内部保留的（`_import`、`_hub`），不允许。
- **前缀**：可选。1 到 8 个字符，只含字母、数字、汉字，英文不分大小写；不能与别的项目的前缀重复（英文大小写不同也算重复）；不能是"服务"（服务自己的指令用）；不能是确认词（见 `hub-inbox`：对、是、确认、好、ok、yes、y）。
- **保底、上限**：整数，`0 ≤ 保底 ≤ 上限 ≤ 窗口总条数 − 回复保留`；所有启用的项目的保底之和加上回复保留 MUST 不超过窗口总条数，超了就拒绝并列出现在每个项目的保底。
- **默认项目**：同一时间最多一个。第一个登记的项目自动成为默认项目；之后加 `--default` 才把默认换成它（要再加 `--yes` 确认，输出写明原来的默认项目是谁）。
- **标签**：回复和推送的第一行前面加的 `【标签】`。默认项目默认没有标签（现在的用法一个字都不用变）；其他项目默认标签是前缀（没有前缀时是名字）；`--no-label` 关掉。
- **只推送**（`--push-only`）：只发消息、不取话的项目。不能有前缀，不能是默认项目；调用取话接口得到 403 `push_only`。

#### Scenario: 第一个项目成为默认项目

- **WHEN** 登记第一个项目 `ashare-quant`，前缀 `量化`，保底 6，上限 8
- **THEN** 打印一次密钥（`chub_` 开头），`hubctl project list` 里它是默认项目，没有标签

#### Scenario: 总保底超了

- **WHEN** 窗口总条数 10、回复保留 2，已有项目保底 6，再登记一个保底 4 的项目
- **THEN** 拒绝，提示"保底合计 10 加上回复保留 2 超过窗口总条数 10"，并列出现有各项目的保底；没有新增项目

#### Scenario: 前缀重复

- **WHEN** 登记前缀 `X` 的项目，已有一个前缀 `x` 的项目
- **THEN** 拒绝，提示前缀已被谁占用

#### Scenario: 前缀不合规

- **WHEN** 前缀是 `服务`、`对`，或者 9 个字、含空格或标点
- **THEN** 都拒绝，各自说明原因

#### Scenario: 只推送项目

- **WHEN** 登记 `--push-only` 同时给了 `--prefix`
- **THEN** 拒绝，说明只推送的项目没有前缀

### Requirement: 项目密钥

密钥 MUST 是 `chub_` 加 43 个 URL 安全的 base64 字符（32 字节随机数）。数据库里 MUST 只存它的 SHA-256 摘要，不存原文；密钥只在登记和换钥时显示一次。所有接口 MUST 从请求头 `Authorization: Bearer <密钥>` 认项目，比较用恒定时间。

- 没带、格式不对或者认不出来：401 `unauthorized`，返回内容与"项目不存在"完全一样，不透露是哪一种。
- 项目已停用：403 `project_disabled`。
- 同一个来源地址 1 分钟内认证失败 10 次，之后的请求一律 429 `too_many_failures`（带 `Retry-After: 60`），直到过去 1 分钟没有新的失败。
- 日志里只出现项目名，不出现密钥或密钥的任何一段。

`hubctl project rotate <名字> [--grace <分钟>]` 生成新密钥（打印一次），旧密钥立刻失效；`--grace` 让旧密钥再用若干分钟（最多 60，默认 0），给项目换配置留时间。

#### Scenario: 错误的密钥

- **WHEN** 用一把没登记过的密钥调 `GET /v1/status`
- **THEN** 401 `unauthorized`；用一个已停用项目的密钥得到的是 403 `project_disabled`

#### Scenario: 数据库里没有密钥原文

- **WHEN** 登记项目后检查数据库文件的全部内容
- **THEN** 找不到密钥原文，只有摘要

#### Scenario: 反复猜密钥

- **WHEN** 同一来源地址 1 分钟内用错误的密钥请求 10 次，第 11 次用正确的密钥
- **THEN** 第 11 次也是 429；过 1 分钟后正确的密钥恢复可用

#### Scenario: 换钥

- **WHEN** `rotate` 不带 `--grace`
- **THEN** 新密钥可用，旧密钥立刻 401；带 `--grace 10` 时旧密钥 10 分钟内仍可用，之后 401

### Requirement: 修改、停用、启用、移除

- `hubctl project set <名字> [--prefix …] [--guaranteed …] [--cap …] [--label …]`：改完同样要通过登记时的校验，对下一个请求立即生效。
- `hubctl project disable <名字>`：立即生效。正在发的那一条发完；它还没取走的话保留为"暂停"，重新启用后继续取（超过保留期仍作废）；它没用完的保底从保护范围里放掉，别的项目马上能用。
- `hubctl project enable <名字>`：重新校验保底总和，超了就拒绝。
- `hubctl project remove <名字>`：必须先停用；释放它的前缀；记录保留，名字不能再被新项目用。移除默认项目前必须先指定另一个默认项目；服务里没有默认项目时，没有前缀的话由服务回一句"没有默认项目，这句话没处理"。

#### Scenario: 停用后立刻断开

- **WHEN** 停用一个项目，它紧接着发消息和取话
- **THEN** 都是 403 `project_disabled`；它没用完的保底不再占着额度

#### Scenario: 启用时保底超了

- **WHEN** 停用的项目保底 4，期间别的项目把保底提到 6（合计超出），再启用它
- **THEN** 拒绝启用并说明超了多少

#### Scenario: 移除

- **WHEN** 对一个启用中的项目执行 `remove`
- **THEN** 拒绝，提示先 `disable`；停用后 `remove` 成功，同名项目不能再登记，它的前缀可以被别的项目使用

### Requirement: 项目之间互相看不到

每个请求 MUST 只能碰到自己项目的东西：取话只返回路由给自己的话；回复句柄只对被路由给自己的那句话有效，用别的项目的句柄或不存在的句柄一律 404 `unknown_handle`（两种情况返回一样）；去重键、发送记录、额度用量按项目分开，同一个去重键在两个项目里互不影响。`GET /v1/status` 只返回全局的登录和窗口信息，加上调用方自己的额度，不返回别的项目的名字和用量。

#### Scenario: 用别人的回复句柄

- **WHEN** 项目 B 拿着路由给项目 A 的那句话的回复句柄调用回复接口
- **THEN** 404 `unknown_handle`，没有向微信发任何东西

#### Scenario: 去重键各管各的

- **WHEN** 项目 A 和项目 B 各用同一个去重键 `daily` 发一条消息
- **THEN** 两条都发出去，互不影响

### Requirement: 请求限速和大小

`POST /v1/messages` 与 `POST /v1/replies` 合计，每个项目每分钟最多 30 次（配置 `send.rate_per_minute`，滑动窗口）。超出的请求 MUST 返回 429 `rate_limited` 并带 `Retry-After`（秒），不占额度、不留发送记录。任何请求体超过 64 KiB 返回 413 `too_large`。

#### Scenario: 一个项目刷屏

- **WHEN** 一个项目在 1 分钟内连续发 31 次请求
- **THEN** 前 30 次按各自的规则处理，第 31 次得到 429 `rate_limited`；别的项目不受影响

### Requirement: 项目在线判断

项目只要 90 秒内（配置 `inbox.online_seconds`）完成过一次 `GET /v1/inbox`（等到新话返回、等满超时返回空都算），或者此刻有一个取话请求正挂着，就算"在线"。"在线"用于路由（见 `hub-inbox` 的项目离线）和状态显示；它不影响发消息：只推送的项目永远不是"在线"，照样可以发。每次认证成功的请求都 MUST 更新这个项目的"最后出现"时间。

#### Scenario: 取话停了

- **WHEN** 一个项目最后一次取话是 2 分钟前
- **THEN** `hubctl project list` 里它显示离线，"最后出现"是它最近一次任何请求的时间

### Requirement: 查看

`hubctl project list [--json]` 列出每个项目：名字、前缀、是不是默认、标签、保底、上限、是否启用、是否只推送、在线与否、最后出现、当前窗口已用条数；服务内部用的 `_hub`、`_import` 不列。`hubctl project show <名字>` 看一个。输出里 MUST NOT 有密钥或摘要。已移除的项目默认不列，加 `--all` 才列（标明已移除）。

#### Scenario: 列表

- **WHEN** 登记了两个项目后执行 `hubctl project list`
- **THEN** 每个项目一行，包含以上各项；输出中搜不到 `chub_`
