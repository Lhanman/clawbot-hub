# 安装说明

在家里的 Mac mini 上把 clawbot-hub 从零装起来、跑起来。每一步都写了命令和**预期输出**：对不上就先停下来，看最后的「出毛病怎么办」，不要接着往下做。

代码在云里写、在 Mac 上装。扫码绑定和装 launchd 只能在 Mac 上（家里的网络）做。

## 开始之前

三件事先记住：

1. **演练和正式分开。** 第一次装先做一遍演练：用单独的数据目录 `~/.clawbot-hub-rehearsal`、单独的端口 18790、另一个 launchd label `com.clawbot-hub.rehearsal`，连的是本机上的假腾讯，**不碰真实的 ClawBot**。演练完整个演练目录移走，正式的数据目录 `~/.clawbot-hub` 里不留演练的东西（指向假腾讯的 `account.json`、演练登记的项目）。演练的做法见后面的「演练：用假腾讯走一遍」，正式安装就是下面的第 1 到第 9 步。
2. **停服务一律写 `launchctl bootout`。** 它把任务整个从 launchd 里摘掉：先发停止信号，等服务把正在发的那一条发完、写好收尾的记录（最多 45 秒，模板里的 `ExitTimeOut`），不退才强杀。单独 `kill` 或 `launchctl stop` 只是结束这一次进程，任务还挂在 launchd 里，什么时候又被拉起来要看退出码，容易让人以为停住了其实没有。
3. **局域网监听是明文的。** 服务默认只听本机 `127.0.0.1:8790`，这时什么都不用担心。只有你把配置 `server.lan` 打开（让别的机器上的项目也能用），项目密钥才会明文走局域网，所以只在可信的家庭网络里开；不做 TLS，也不支持公网。细节见后面的「局域网监听（可选）」。

需要的东西：

| 要什么 | 说明 |
|---|---|
| 一台 Mac（macOS，能一直开着） | 登录后自启动，所以要登录到桌面用户 |
| 命令行里能用 `git` 和 `uv` | 没有 `uv` 的话下面第 1 步装 |
| Bark（iPhone 上的 App）和它的设备码 | 服务出问题时通知你；不配也能跑，但出了事你不会知道 |
| 手机微信 | 扫码绑定 ClawBot 时用（正式安装才需要） |
| 对 GitHub 仓库 `Lhanman/clawbot-hub` 的读取权限 | 仓库是公开的，不用登录 |

## 第 1 步：装 uv 和 git

```
command -v git uv
```

预期输出：两行路径（`/usr/bin/git`、`…/uv`）。缺 `git` 的话运行 `xcode-select --install`；缺 `uv` 的话：

```
curl -LsSf https://astral.sh/uv/install.sh | sh
```

装完**重新打开一个终端窗口**，再运行 `command -v uv`，预期输出一行 `uv` 的路径（后面第 8 步要用）。

## 第 2 步：拿代码、装依赖

```
git clone https://github.com/Lhanman/clawbot-hub.git ~/clawbot-hub
cd ~/clawbot-hub
uv sync
uv run hubctl --help
```

预期输出：`git clone` 打印 `Cloning into …`；`uv sync` 最后几行是 `Installed N packages`（或 `Audited N packages`）；`hubctl --help` 列出全部命令：`serve`、`login`、`import-credentials`、`status`、`project`、`send`、`alerts`、`doctor`、`backup`、`events`、`config`、`version`，每条一句中文说明。

> Python 要 3.12 以上，`uv sync` 会自己去装合适的版本，不用手动装。

## 第 3 步：定数据目录

数据目录放所有数据：登录凭证、数据库、告警设备码、日志、备份。默认是 `~/.clawbot-hub`，由环境变量 `CLAWBOT_HUB_HOME` 改（每个命令也认 `--home`，写在子命令后面，例如 `hubctl status --home …`）。

| | 数据目录 | 端口 | launchd label |
|---|---|---|---|
| **正式** | `~/.clawbot-hub`（什么都不用设） | 8790 | `com.clawbot-hub.serve` |
| **演练** | `~/.clawbot-hub-rehearsal` | 18790（假腾讯 18791） | `com.clawbot-hub.rehearsal` |

演练的话，**这个终端窗口里**先设：

```
export CLAWBOT_HUB_HOME=~/.clawbot-hub-rehearsal
```

正式安装时不设它（也确认一下当前窗口里没有残留：`echo "${CLAWBOT_HUB_HOME:-没设}"` 预期输出 `没设`）。

预期：这一步没有输出，也还没有建目录；下一步第一次运行 `hubctl` 命令时才会建出来，权限 0700。

## 第 4 步：先检查一遍

```
uv run hubctl doctor
```

预期输出：每项一行，以 ✓（通过）、⚠（警告）、✗（错误）开头，最后一行汇总。这时候应该**没有 ✗**，只有这几个 ⚠：数据目录是刚建的（也许 `--home` 指错了，确认没指错就行）、还没绑定、服务没有在运行、没配告警设备码。退出码是 0。下面是一份真实的输出（数据目录那一行实际写的是完整路径，这里缩写成 `~/.clawbot-hub`；磁盘空间是你机器上的数）：

```
⚠ 数据目录：~/.clawbot-hub 是这次运行刚建的：如果这不是你要看的那个目录，多半是 --home 或环境变量 CLAWBOT_HUB_HOME 指错了；确认没指错就不用管
✓ 权限：数据目录 0700，里面的文件 0600，没有放宽的
⚠ 登录凭证：还没绑定：运行 hubctl login 扫码绑定，或者用 hubctl import-credentials 接过 ashare-quant 的凭证
✓ 数据库：还没有（服务第一次启动或登记第一个项目时建）
⚠ 服务：没有在运行（如果是你有意停的，不用管）
✓ 端口：127.0.0.1:8790 空着
✓ 配置：没有 config.yaml，用的是内置默认值
⚠ 告警设备码：没有配置告警，服务出问题时不会通知你：运行 hubctl alerts set-key
✓ 配置警告：没有
✓ 扫码标记：没有残留的 login.pending
✓ 磁盘空间：还剩 28.1 GB
✓ 自动备份：还没有数据库，没有什么可备份的
汇总：8 项通过，4 个警告，0 个错误
```

有 ✗ 的话照提示改；权限太宽可以加 `--fix` 自动改回。

## 第 5 步：配置告警（Bark）

服务出问题（登录失效、窗口快到期、腾讯不通、服务重启……）时，只通过 Bark 告诉你，不走微信。设备码从 Bark App 里复制（只填设备码，或者粘贴 App 里的整个推送地址都行）：

```
uv run hubctl alerts set-key
```

敲回车后粘贴设备码再回车（它从标准输入读，不会出现在命令历史里）。然后发一条测试：

```
uv run hubctl alerts test
```

预期输出：`set-key` 打印「设备码已保存到 bark.json（权限 0600）。运行 hubctl alerts test 发一条测试告警。」；`test` 打印「测试告警已送到：Bark 收下了，手机上应该很快会收到一条标题含「测试」的通知。」，退出码 0；手机上收到一条标题含「测试」的 Bark 通知。设备码存在 `<数据目录>/bark.json`（权限 0600），**命令的输出里不会出现设备码**。

收不到的话先看 `hubctl events --kind alert`：写着「被拒绝」多半是设备码填错了，重新 `set-key`。

## 第 6 步：绑定 ClawBot

**正式安装**（真账号，需要手机微信）：

```
uv run hubctl login
```

预期输出：终端里画出一张二维码（同时存一张 `<数据目录>/clawbot-login.png`），下面一行「用微信扫上面的二维码（约 2 分钟有效，过期会自动换新码）；也可以打开图片 …/clawbot-login.png」；用手机微信扫一扫，在手机上确认；终端最后一句是「绑定成功。现在在微信里给 ClawBot 发任意一句话，之后 24 小时内它才能给你发消息。」，退出码 0。二维码过期会提示「二维码过期了，换一张新的」，连续 5 张都没扫就退出，凭证不变，重新运行即可。要验证码的话照提示输入微信里显示的数字。

**马上照提示做**：在微信里给 ClawBot 发一句话（随便什么）。

> 不要为了试试看而重复扫码：一个微信号可能只认最后一次扫码，重复扫会把正在用的绑定挤掉。已经绑定过的情况（比如从 ashare-quant 迁过来），用 `hubctl import-credentials`，见《迁移手册》。

**演练**：这一步不连真账号，要先在另一个终端窗口里把假腾讯起起来，并让服务指向它，见后面的「演练：用假腾讯走一遍」。

## 第 7 步：登记项目

每个要用微信的项目登记一次。以 ashare-quant 为例（保底 6 条、上限 8 条，前缀「量化」，设为默认项目）：

```
uv run hubctl project add ashare-quant --prefix 量化 --guaranteed 6 --cap 8 --default
```

预期输出：

```
已登记项目 ashare-quant（前缀「量化」，保底 6、上限 8，默认项目）
密钥（只显示这一次，请马上存好，之后任何命令都不再显示）：
chub_……（一长串）
提醒：服务分不清默认项目自己的指令里有没有和前缀「量化」同名的词。例如前缀取「状态」，默认项目整句「状态」就会被交给这个项目；请自己确认。
```

最后一行「提醒」凡是带前缀的项目登记时都有（`hubctl project set` 改前缀时也有）：默认项目会收到所有不带前缀的话，它自己的指令要是恰好和某个前缀同名，服务分不清该交给谁，所以请你扫一眼，不是出错。

**这把密钥马上存进密码管理器或钥匙串**，之后任何命令都不会再显示它；丢了只能 `hubctl project rotate` 换一把。不要贴进聊天或提交进 git。看一眼登记结果：

```
uv run hubctl project list
```

预期输出：一行 `ashare-quant（前缀「量化」，默认项目）：保底 6、上限 8，本窗口已推送 0 条、回复 0 条；离线；……`。「离线」是因为项目还没来取过话，正常。

其他项目照样登记，保底合计加上回复保留（默认 2）不能超过窗口总条数（默认 10）；超了会被拒绝并说明。

## 第 8 步：装 launchd，让它常驻

launchd 模板在 `deploy/launchd/com.clawbot-hub.serve.plist.example`，里面有四个占位符，用 `sed` 换成你的实际路径，写进 `~/Library/LaunchAgents/`：

```
cd ~/clawbot-hub
mkdir -p ~/Library/LaunchAgents
sed -e "s|__LABEL__|com.clawbot-hub.serve|g" \
    -e "s|__REPO_DIR__|$HOME/clawbot-hub|g" \
    -e "s|__UV_PATH__|$(command -v uv)|g" \
    -e "s|__DATA_DIR__|$HOME/.clawbot-hub|g" \
    deploy/launchd/com.clawbot-hub.serve.plist.example \
    > ~/Library/LaunchAgents/com.clawbot-hub.serve.plist
plutil -lint ~/Library/LaunchAgents/com.clawbot-hub.serve.plist
```

（演练：`__LABEL__` 换成 `com.clawbot-hub.rehearsal`，`__DATA_DIR__` 换成 `$HOME/.clawbot-hub-rehearsal`，文件名也用 `com.clawbot-hub.rehearsal.plist`。）

预期输出：`plutil -lint` 打印 `….plist: OK`。模板里的要点：登录后自启动（`RunAtLoad`）；只有崩溃或非 0 退出才拉起（`KeepAlive` 是 `SuccessfulExit: false`），所以你手动停它不会被立刻拉回来；`ThrottleInterval` 30 秒，避免反复空转；`ExitTimeOut` 45 秒，给优雅关停留够时间；`Umask` 63（即 077），保证它建的文件只有你自己能读；日志写到 `<数据目录>/logs/launchd.log`。

启动：

```
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.clawbot-hub.serve.plist
```

预期输出：没有输出（launchd 的习惯：没消息就是成功）。过几秒后看日志文件的权限：

```
ls -l ~/.clawbot-hub/logs/
```

预期输出：`hub.log` 和 `launchd.log` 都是 `-rw-------`（0600）。**`launchd.log` 是 launchd 在服务启动之前建的**，它的权限由 launchd 决定，`Umask` 对它管不管用要在真机上看（《真机验证清单》里有这一项）：如果不是 `-rw-------`，服务启动时会把它改回 0600 并在 `hub.log` 里记一条警告；你也可以把模板里的标准输出和标准错误改指向 `/dev/null`（服务自己已经写 `hub.log`）。

## 第 9 步：确认服务在跑

```
uv run hubctl status
curl -s http://127.0.0.1:8790/v1/health
uv run hubctl doctor
```

预期输出：

- `status` 的样子见下面（进程号、时间、版本是你机器上的）；
- `curl` 返回恰好 `{"ok":true,"version":"0.1.0","api":"1"}`，没有别的字段；
- `doctor` 没有 ✗，⚠ 最多一个：「自动备份：一份也没做过」。服务启动时如果已经过了当天的备份时间，会马上补做今天的一份，几秒钟后再运行 `doctor` 它就没了；还没到备份时间的话等到点，或者现在手动运行 `hubctl backup`。

```
服务：在运行（进程号 32242，已运行 不到 1 分钟），版本 0.1.0，监听 127.0.0.1:8790，上游档位 legacy，送达确认 observe
登录：已绑定（10月17日 00:43 绑定，机器人号 ….bot）
  收消息：最近一次成功 还没有，最近一次出错 没有
  忽略的陌生人消息：0 条
对话窗口：还没收到过你的消息
项目：
  ashare-quant（前缀「量化」，默认项目）：保底 6、上限 8，本窗口已推送 0 条、回复 0 条；离线；最后出现 还没有
待处理：没有
```

再看一眼窗口：在微信里给 ClawBot 发一句话，几秒后 `hubctl status` 的「对话窗口」会变成（项目这时还没来取话）：

```
对话窗口：开着（10月17日 00:43 起，还剩约 23 小时 59 分钟）
  已用 1/10 条（推送 0、回复 1）
  腾讯拒绝后暂停：否
项目：
  ashare-quant（前缀「量化」，默认项目）：保底 6、上限 8，本窗口已推送 0 条、回复 0 条；离线；最后出现 还没有
待处理：
  等着项目取的话：ashare-quant 1 条
```

窗口剩余约 24 小时。「已用 1」是服务自己回的那一句：项目还没来取话，服务会回你一句「【服务】「量化」现在没在线。这句话我先留着：10 分钟内它回来就会处理，超过就作废」，这一句算一条回复，微信里收到它是正常的。

`hubctl events` 里，第一次启动后会有一条「登录凭证已更换：对话窗口作废，换用新凭证」：服务第一次启动时把登录凭证的摘要记进数据库，不是出错。

到这里就装好了。项目那一侧怎么接，看 `docs/clients/接入指南.md`。

## 演练：用假腾讯走一遍

正式安装之前，在 Mac 上用**单独的数据目录和端口**演练一遍，确认装得上、起得来、收得到、发得出、断网能恢复、停得下来。全程不碰真实的 ClawBot。

先开一个终端窗口（窗口 A）把假腾讯起起来（仓库里的 `tests/support/fake_ilink.py`，独立运行模式）：

```
cd ~/clawbot-hub
uv run python -m tests.support.fake_ilink --port 18791
```

预期输出：`fake_ilink listening on http://127.0.0.1:18791`，然后一直挂着（别关）。它会在取码 3 秒后自动把二维码变成「已确认」，所以演练里的扫码不需要手机。

另开一个窗口 B，做第 3 步的 `export CLAWBOT_HUB_HOME=~/.clawbot-hub-rehearsal`，写演练配置：

```
mkdir -p ~/.clawbot-hub-rehearsal && chmod 700 ~/.clawbot-hub-rehearsal
cat > ~/.clawbot-hub-rehearsal/config.yaml <<'EOF'
server:
  port: 18790
upstream:
  base_url: "http://127.0.0.1:18791"
EOF
chmod 600 ~/.clawbot-hub-rehearsal/config.yaml
```

然后在窗口 B 里按正式安装的第 4 到第 9 步走一遍，只有这些地方不一样：

- 第 6 步：`uv run hubctl login`，终端里画出二维码后**不用扫**，3 秒后假腾讯自动确认；
- 第 7 步：登记一个叫 `ashare-quant` 的项目（和正式的同名，反正演练完整个目录要移走）；
- 第 8 步：label、plist 文件名和数据目录换成演练的（见第 8 步括号里的说明）；
- 第 9 步：`curl` 的端口换成 18790。

服务起来以后，演练下面几件事：

| 做什么 | 怎么做 | 预期 |
|---|---|---|
| 收一条（先做这一条） | `curl -s -X POST http://127.0.0.1:18791/_fake/inbox -H 'Content-Type: application/json' -d '{"text":"量化 状态"}'`，几秒后 `hubctl status` | 对话窗口开了（演练里“使用者说过话”就靠这一条）；ashare-quant 的待处理里多一条待取的话（项目没来取之前一直排队）；再放一条不带前缀的话也会路由给默认项目 |
| 发一条 | `export CLAWBOT_HUB_KEY=<演练里登记时打印的密钥>`，`uv run hubctl send --url http://127.0.0.1:18790 "演练：发一条"` | 输出 `sent`，退出码 0；窗口 A 外另开一个窗口 C 运行 `curl -s http://127.0.0.1:18791/_fake/sent` 能看到这一条。使用者还没说过话（没做上一行）时得到 `rejected`：窗口没开，这是对的 |
| 断一次网 | `curl -s -X POST http://127.0.0.1:18791/_fake/mode -H 'Content-Type: application/json' -d '{"mode":"disconnect"}'`，等几十秒，再切回 `{"mode":"normal"}` | 断开期间 `hubctl send` 得到 `unconfirmed`（腾讯没回话，可能已经到了；连不上才是 `failed`），恢复后一切正常；服务没有退出 |
| 登录失效 | 扫码成功一分钟以后再做（刚换上新凭证的 60 秒内收到 -14 不算失效，见《设计方案》）；切到 `{"mode":"session_expired"}`，再 `hubctl send` 一条 | `hubctl status` 显示登录已失效，手机收到「登录失效」的 Bark；切回 `normal` 后下一次探测恢复（最长 10 分钟，或者重新 `hubctl login` 马上恢复） |
| 重启 | `launchctl bootout gui/$(id -u)/com.clawbot-hub.rehearsal`，再 `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.clawbot-hub.rehearsal.plist` | 正常停（`hubctl status` 显示没有在运行），再起后窗口、待取的话、告警状态都还在；**没有**「服务重启」的 Bark（正常退出不算出事） |
| 停掉 | `launchctl bootout gui/$(id -u)/com.clawbot-hub.rehearsal` | 同上，服务停了，launchd 没把它拉回来 |

演练完，**把整个演练目录移走**（别留在正式位置附近，也别删到找不回来之前的日志）：

```
launchctl bootout gui/$(id -u)/com.clawbot-hub.rehearsal 2>/dev/null
rm -f ~/Library/LaunchAgents/com.clawbot-hub.rehearsal.plist
mv ~/.clawbot-hub-rehearsal ~/.clawbot-hub-rehearsal.done-$(date +%Y%m%d)
unset CLAWBOT_HUB_HOME
```

在窗口 A 里按 Ctrl-C 关掉假腾讯。预期：`ls ~/.clawbot-hub` 里没有演练遗留（正式目录下的 `account.json` 里 `base_url` 不是 `127.0.0.1`，`hubctl project list` 里没有演练登记的项目）；《迁移手册》的第 1 步会再检查一遍。

## 日常：停、起、重启、升级、备份

**停服务**（任何时候都用这个）：

```
launchctl bootout gui/$(id -u)/com.clawbot-hub.serve
```

服务会拒绝新请求、把正在发的那一条发完（最多 35 秒）、写下正常退出的标记，再退出。预期：`hubctl status` 第一行是「服务：没有在运行」，不会有「服务重启」的告警。

**起服务**：

```
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.clawbot-hub.serve.plist
```

**改了配置要重启**：`config.yaml` 只在服务启动时读一次，改完先 `bootout` 再 `bootstrap`。`hubctl config show` 会在配置文件比服务启动得晚时提示「配置文件改过，重启服务才生效」。

**升级**：

```
launchctl bootout gui/$(id -u)/com.clawbot-hub.serve
cd ~/clawbot-hub && git pull && uv sync
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.clawbot-hub.serve.plist
uv run hubctl doctor
```

启动时数据库会自动升级，升级之前自动备份一份（名字以 `pre-upgrade-` 开头）。数据库比程序新的话服务会拒绝启动（退出码 3），**不要回退程序**，去拉新代码。

**备份**：服务每天 04:00（显示时区的 04:00：配置 `display.timezone`，默认 `Asia/Shanghai`，也就是北京时间；Mac 本机在东京的话是 05:00）自动备份一份到 `<数据目录>/backups/auto-<时间>/`，保留最近 14 份。手动备份用 `uv run hubctl backup`（服务运行时也安全）。**备份里有登录凭证**，不要放进云盘或 git。

## 局域网监听（可选）

默认只有本机上的项目能连服务。如果别的机器上的项目也要用，在 `config.yaml` 里写：

```yaml
server:
  lan: true
```

这时服务监听 `0.0.0.0:8790`，但**只接受本机和私有网段**（10.x、172.16 到 31.x、192.168.x、169.254.x 和 IPv6 的本地地址）的连接，其他来源一律 403。`lan: true` 时 `server.host` 必须保持默认值，`lan: false` 时 `host` 必须是回环地址，配错了服务拒绝启动。

**这条路上没有 TLS：项目密钥是明文走局域网的**，所以只在可信的家庭网络里开；不要把端口映射到公网；路由器里别给这台机器开端口转发。改完配置要重启服务。

## 出毛病怎么办

| 现象 | 怎么办 |
|---|---|
| `hubctl doctor` 报权限太宽 | 加 `--fix`，或者 `chmod 700 <数据目录>`、`chmod 600 <数据目录>` 下的文件 |
| 服务起不来，提示「端口 8790 已被占用」 | 另一个程序占着端口：`lsof -nP -iTCP:8790 -sTCP:LISTEN` 看是谁；演练和正式的端口不能撞 |
| 提示「已经有一个在运行（进程号 N）」，退出码 2 | 服务已经在跑了（`hubctl status` 确认）；或者有 `hubctl import-credentials` 正在导入，等它做完 |
| 提示「数据库版本比程序新，请升级程序，不要回退」，退出码 3 | `git pull && uv sync`；不要用旧程序打开新库 |
| 配置有错，退出码 1 | 错误一次列全，照着改；改完重新 `bootstrap` |
| `hubctl status` 说登录已失效 | 在电脑上 `uv run hubctl login` 重新扫码，服务 5 秒内自动换上新凭证，不用重启 |
| 手机收不到 Bark | `hubctl alerts test` 看结果；`hubctl doctor` 会提示 Bark 是不是被拒绝过；设备码错了就重新 `set-key` |
| 项目发消息得到 `rejected`（窗口过期了） | 在微信里给 ClawBot 发一句话，窗口就重新开了 |
| 想看服务在做什么 | `tail -f ~/.clawbot-hub/logs/hub.log`；`hubctl events` 看最近的事件（没有消息正文） |
| 完全装乱了 | 先 `launchctl bootout …` 停掉，把数据目录整个移走（不要删），从第 3 步重来；有备份的话见《回退手册》 |

出了拿不准的事，**先停服务、保留现场**（别急着删日志和数据库），再来查。
